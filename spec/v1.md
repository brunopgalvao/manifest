# Manifest MX v1.2

> One tree that the model writes, the screen renders and the model reads back.

v1 replaces v0's syntax after the first benchmark (`bench/results.md`). The model, lifecycle and perception concepts from `v0.md` carry over. What changed is the encoding: v1 is designed against measured token costs, and perception output uses **the same syntax the model writes**.

v1.2 settles the questions the v1.1 writing and reading tests raised. The changes are listed in §10.

---

## 1. Shape of a document

```
@<surface-id> [lifecycle...]
<node line>
  <child node line>
```

- Each line is one node. Indent by two spaces per level to nest.
- Top-level lines are children of an implicit vertical column (`root`).
- Words are separated by spaces.
- **Headings, `text` and `badge`:** everything after the type is the text, so no quotes are needed: `h1 Class feedback`. Trailing tone words (`success`, `danger`…) and `#id` are read as modifiers, so quote the text if it really ends with one: `text "This is a success"`.
- **Everything else** (buttons, inputs, metrics, options…): quote any label with spaces: `button "Export CSV"`. Bare words after the label must be valid flags for that type, and an unknown word is rejected as an error (a typo like `primay` is caught, not ignored).

## 2. IDs: derived, stable, overridable

Every node gets an ID without you writing one:

| Node | Derived ID |
|---|---|
| The first `h1` | `title` |
| A labelled node (text, metric, button, field, select, check, toggle, slider, tab, link, image, badge, and a card with a title) | The first word of the label, lowercased, letters and digits only. `"Export CSV"` → `export`, `card "Pro"` → `pro`. |
| Anything else (other headings, row, col, an untitled card, table, tabs, and charts) | Its type name. A `bar` chart is `bar`, a `line` chart is `line`, a `table` is `table`. A second heading is `h2`, so a heading never takes a button's ID (`h2 Delete?` above `button Delete`). |
| A flow node | Its name, slugged: `Agent` → `agent` |

**Duplicates are scoped by their nearest labelled container** (a `card "Pro"`, a `tab Billing` or a named `flow`): the ID becomes `<container-id>.<base>`. Three cards that each hold `metric Monthly …` and `button Upgrade` give `starter.monthly`, `pro.monthly`, `team.monthly` and `starter.upgrade`, `pro.upgrade`, `team.upgrade`. Only when that still collides, or there is no labelled container, do duplicates get `2`, `3`, … in document order (`row`, `row2`).

- Add `#name` anywhere on the line to choose the ID yourself.
- **IDs are fixed at creation.** Relabelling a button doesn't change its ID, and a node inserted later never renames an existing one. Perception prints `#id` whenever the ID is not what these rules would derive from the current tree, so you never have to remember it.

## 3. Node types

Arguments are positional, in the order shown. `[...]` means optional. Flags are bare words.

### Layout
| Line | Meaning |
|---|---|
| `row [end\|center\|between]` | Horizontal group. The flag sets alignment. |
| `col` | Vertical group. |
| `card ["Title"]` | Bordered container. A title gives it an ID (`card "Pro"` → `pro`) and makes it a labelled container for ID scoping. |
| `grid <cols>` | Grid, e.g. `grid 3`. |
| `tabs` | Children are `tab` lines. |
| `tab [*]Label` | A tab. `*` marks the selected one. Children are its content. |

### Content
| Line | Meaning |
|---|---|
| `h1\|h2\|h3 Text` | Heading. |
| `text Text [tone]` | Paragraph. |
| `badge Text [tone]` | Pill label. |
| `image <src> "alt text"` | Alt text is required. Painted at natural size, never upscaled, scaled down only to fit the column, no rounding: a screenshot comes back pixel for pixel. |
| `link Text <url>` | The host confirms before opening. |

**Tones** are the six words every model already knows as colours from CSS frameworks:

| Tone | Colour | Use |
|---|---|---|
| `primary` | blue | the main action, emphasis |
| `success` | green | good, done, up |
| `danger` | red | bad, destructive, down |
| `warning` | amber | needs attention |
| `info` | cyan | neutral note |
| `muted` | grey | de-emphasised |

A tone is one word and goes on any node that shows colour: text, badges, metrics, buttons, flow nodes and badge cells. Perception prints the same word, so a reader sees `Perception:success` and knows that box is green.

### Data
| Line | Meaning |
|---|---|
| `metric Label Value [Delta] [tone]` | A KPI. The tone defaults from the delta sign (`+` is `success`, `-` is `danger`). Override it when that's wrong, e.g. churn going up: `metric Churn 2.1% +0.4pt danger`. |
| `bar\|line\|area\|pie ["Caption"] Key:Num ...` | A chart. Its ID is its type (`bar`, `line`). `*` before a datum highlights it: `*Sep:73`. |
| `table Col Col:badge ...` | A table. Child lines are rows with ` \| `-separated cells (spaces around `\|` optional). **The first cell, exactly as written, is the row key**: a row `search \| ap-south \| Down` is addressed `table.search`, and a row `#1044 \| …` is addressed `table.#1044`. `:badge` renders that column as badges (see below). |
| `flow ["Caption"]` | A diagram with automatic layout. Child lines are chains: `A >label B >label C`. Add `Name:tone` to colour a node. Trailing flags (`dashed`, `below`) apply to every edge on that line. |

**Badge cells.** A cell in a `:badge` column takes an explicit tone with the same `:tone` suffix a flow node uses: `Refunded:danger`. Without one, the renderer picks from a fixed word list, and anything else is `muted`:

| Tone | Words (case-insensitive) |
|---|---|
| `success` | paid, done, active, ok, operational, passed, up, open, live, healthy |
| `warning` | pending, degraded, warning, slow, partial, review, draft |
| `danger` | failed, down, error, refunded, blocked, overdue, critical, cancelled |
| `info` | new, info, scheduled, queued |

Perception prints a `:tone` only where it was written, since the list is fixed and the reader can apply it too.

### Input
Each input's value lives in the data model at `/<id>` (A2UI-compatible), and its initial value is written inline.

| Line | Meaning |
|---|---|
| `button Label [tone] [disabled]` | Sends action `<id>` when pressed. `primary` is the main action and `danger` a destructive one. Several `primary` buttons are allowed, but one per surface is the convention. |
| `field Label [email\|date\|number\|search\|password] [="value"] [required]` | A text input. |
| `select Label Opt *Opt Opt [multi]` | `*` marks the selected option. |
| `check Label on\|off` | Checkbox. |
| `toggle Label on\|off` | Switch. |
| `slider Label <value> [min..max]` | The range defaults to `0..100`. |

**Validation:** every input and button needs a label, and every image needs alt text. The host rejects the block, with the line number, if one is missing.

## 4. Lifecycle (on the `@` line)

| Word | Dissolves when |
|---|---|
| *(nothing)* | Persistent: dissolves only when the model or the user closes it. |
| `ephemeral` | The next model turn starts. |
| `ttl:10s` | 10 seconds after it first became visible (wall-clock). Use this for toasts. |
| `until:action` / `until:<id>` | Any action fires, or that button is pressed. |
| `seen:10s` | It has been on screen for a total of 10 seconds. Time spent scrolled away or in a background tab doesn't count. Use this for things the user must actually see. |
| `residue:none\|line\|archive` | What remains afterwards. `none`: the whole surface, buttons included, is gone. `line`: a one-line summary stays on screen and in `observe` listings: the title, or the first text (`@saved dissolved: Settings saved`). `archive`: gone from the screen, but the model can still `observe` it. |

Several conditions mean whichever comes first: `@confirm until:action ttl:60s residue:line`.

## 5. Patches

```
~<rev>                  or  ~<surface> <rev>
*<addr> <args>          set (merge)
+<addr> <node line>     insert directly after addr (as its next sibling); <addr>/ appends inside it
+<table>/ a | b | c     append a table row; +<table>.#key a | b | c inserts after that row
-<addr>                 remove
```

**Binding to a surface.** A patch is bound to the surface named by the call that carries it (`manifest.patch(surface, patch)`, or the A2UI `surfaceId`). Where there is no call, such as a plain text stream, name the surface on the first line: `~dash 4`. If both are given they must agree.

A new surface is at rev 0, so its first patch is `~1`. Each `~rev` must be the next revision. A stale patch is rejected, and you re-observe. **Every address must resolve**: a patch that names a missing node, row or datum is rejected as a whole, never silently skipped.

**Addresses**
| Address | Targets |
|---|---|
| `export` | The node with that ID |
| `pro.upgrade` | A scoped ID (§2) is an ordinary ID |
| `bar.Sep` | A chart datum, by key |
| `table.#1044` | A table row, by its first cell |
| `table.#1044.Status` | A table cell |
| `perception>agent` | A flow edge |

The host resolves the longest leading part of an address that is an ID, then reads the rest as a datum, row or cell.

**Setting (`*`):** positional args set the node's **primary value**:
- Metric: value, then delta.
- Field and slider: the value.
- Select: the chosen option. `+Opt` adds an option.
- Tabs: the selected tab's label.
- Text, heading and button: the label.
- Toggle and check: `on` or `off`.
- A badge cell: the text, with an optional `:tone`.

Flags (`enabled`, `disabled`, tones, `solid`, `dashed`) apply directly. Setting a tone replaces the previous one.

```
~4
*revenue $315k +16%
*bar.Sep 80
*export enabled
+bar text "September is a record month" success
-table.#1047
```

## 6. Events (host → model)

```
@form action book rev=5 {"full":"Sam Lee","email":"sam@lee.dev","class":"Yin","send":true}
@form input email ="sam@lee" rev=6
@confirm dissolved reason=until:action rev=7
error line=3 button needs a label
```

Every event names its surface first. `rev` is the surface's revision when the event happened: user input bumps it, because the tree changed, so a patch written before the input is stale and gets rejected. An action carries the whole data model (every input's value), so a form needs no separate read.

## 7. Perception (model → host → model)

`observe [L0|L1|L2] [since=<rev>] [focus=<id>]` returns **MX in the same syntax as above**, so whatever you can read you can also write back as a patch.

| Level | Adds |
|---|---|
| **L0** | `@id lifecycle rev=N nodes=N diags=N`. Is it alive, and did anything change? |
| **L1** | The full current tree with live values. Hidden subtrees collapse to a summary (below), flows show `[N nodes]`, and renderer diagnostics (`!overflow` …) are included. |
| **L2** | Plus `@x,y,w,h` boxes (px, surface-relative). Diagnostics: `!overflow <addr> shown/needed`, `!overlap a b`, `!contrast <addr> ratio`, `!tiny <addr>`. |

**Hidden subtrees** (an unselected tab) print the labels of their direct children, up to three, so "is X visible?" can be answered at L1 without opening the tab:

```
tab General [hidden: Dark mode, Language, +2]
```

`since=<rev>` returns a patch block instead of the tree, including `+` lines for inserted nodes; it falls back to the full tree only when a change has no patch form (a node changed type, or a diagram changed shape). A new surface is rev 0; every patch and every user input adds one. `look <id>` returns a pixel crop of one node, the only pixel path.

## 8. Mapping to A2UI v0.9

Every MX v1 node maps to an A2UI component with `id` set to the derived ID (a scoped ID such as `pro.upgrade` is used verbatim). Input values map to the data model at `/<id>`. Patches compile to `updateComponents` and `updateDataModel` messages. Lifecycle compiles to a host-side timer plus `deleteSurface`. Perception has no A2UI equivalent, so it's proposed as an extension.

## 9. Transport (MCP)

The reference host is an MCP server with four tools. Any agent that speaks MCP can use it today, without training.

| Tool | Arguments | Returns |
|---|---|---|
| `manifest.render` | `mx` (a full document, starting with its `@` line) | the L0 line, or `error line=N …` |
| `manifest.patch` | `surface`, `patch` | the L0 line after the patch, or the rejection |
| `manifest.observe` | `surface` (omit to list all), `level` (0–2), `since`, `focus`, `wait` (seconds) | MX text. With `wait`, the call returns as soon as an event arrives, or after that many seconds, so a model can wait for the user to answer a dialog without polling. |
| `manifest.look` | `surface`, `id` (omit for the whole surface) | a PNG crop of that node |
| `manifest.dissolve` | `surface` | removes it, honouring `residue` |

Events (§6) that happened since the last call are returned ahead of the tool's own result, one per line, so the model never has to poll for them. The server cannot see model turns, so `ephemeral` surfaces dissolve on the next `manifest.render` call. The full spec is served as the resource `manifest://spec`, and a cheat sheet as the server's instructions.

## 10. Clarifications

Questions three models raised when writing MX from this spec alone (`bench/results.md` §7):

- **Durations** take `ms`, `s`, `m` or `h`: `ttl:2m` and `ttl:120s` are the same.
- **Surface IDs and node IDs are separate namespaces.** A surface `deploy` may contain a button `deploy`; the event reads `@deploy action deploy`.
- **Any word is a valid value.** `41,200`, `$1,920.00` and `+0.4pt` are single words; quote only when a value contains spaces.
- **Labels with spaces are quoted everywhere they are positional**, tabs included: `tab *"Last week"`.
- **`field Search search`** is a field labelled "Search" of kind `search`: the label comes first, then flags.
- **A `tabs` node is addressed as `tabs`** (its type), and `*tabs Month` selects by label with no `*`.
- **The residue line** uses the surface's `title` (the first `h1`, wherever it sits), else its first text.
- **A patch sent without a tool call** names its surface: `~stats 1`. With a tool call, `~1` is enough.

## 11. Changes from v1.1

1. **Scoped IDs.** Duplicate derived IDs inside labelled containers become `<container>.<base>` instead of `monthly2`.
2. **Tones are the CSS-framework words** `primary success danger warning info muted`. `good`→`success`, `bad`→`danger`, `warn`→`warning`, `accent`→`primary`. A button's `primary`/`danger` is now just its tone.
3. **Badge cells** take `:tone`, with a fixed default word list.
4. **Several `primary` buttons** are allowed.
5. **Patch binding** is the call's surface, or `~<surface> <rev>` without a call.
6. **Charts take their type as ID**, stated explicitly.
7. **Hidden tabs list their child labels** at L1 (`[hidden: …]`).
8. **Address resolution** is longest-ID-prefix, so scoped IDs and row keys never collide.
9. **§9 transport** names the MCP tools.
10. **Headings other than the title** take their type name (`h2`), not their first word, so they never collide with a button.
